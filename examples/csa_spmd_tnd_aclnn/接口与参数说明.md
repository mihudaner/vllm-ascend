# CSA ACLNN 接口与参数说明

更新日期：2026-10-27。本文对应1685da69 算法基线及本轮 NZ 接口适配（设备结果见验证清单），替代前期接口分析。使用入口见 [README](README.md)，适配阶段见[接入计划](接入计划.md)。

## 1. 接口分层与数量

| 层次 | 当前合同 |
|---|---|
| 原 Python PTO 业务入口 | 55 项外部 Tensor；不含显式 Top-K 诊断输出 |
| 原 Python PTO 诊断入口 | 57 项外部 Tensor，增加 Top-K 索引和分数 |
| PreparedAclnnCSA / Torch | 使用 57 项 Tensor 列表和一个 `variant`；业务输入缺少 Top-K 时在准备阶段分配两项输出 |
| ACLNN C API | 按注册顺序传输入、`variant` 和 8 项输出；5 项 cache/state 在输入及输出位置复用同一存储 |
| 生成核包装 | 133 个 Tensor 指针及 28 个运行时标量：57 项外部映射、70 项内部申请、6 项内部别名视图 |

这些数量是接口位置/对象数，不代表互不重叠的存储块。例如外部 `hc_base_2d` 与 `hc_base` 共用存储；内部别名也不重复申请。调用者无需额外提供 133 个业务 Tensor。

## 2. 调用与返回

```python
prepared = PreparedAclnnCSA(
    native_inputs,
    library="/path/to/csa_pto_npu.so",
    max_query_tokens=query_upper_bound,
    max_seq_len=history_upper_bound,
    policy=None,
)
output = prepared()  # 原 native_inputs["x_out"]，同时更新 cache/state
```

`native_inputs` 是原 Native 输入字典，包含权重、缓存、页表、metadata 及预分配输出。准备过程复用[上游绑定](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/binding.py)，按完整 `policy.constexprs()` 匹配[manifest](generated/manifest.json)。显式 policy 也必须匹配已有编译策略，否则拒绝。

底层 Torch schema 为 `run(Tensor(a!)[] buffers, int variant) -> ()`：返回 `None`，写入传入的 buffer。Meta 执行描述符检查，不执行计算。列表顺序见下一节；实际调用映射见 [torch/binding.cpp](torch/binding.cpp)。

纯 C++ 使用 `aclnnCsaSpmdTndPtoGetWorkspaceSize` 获取 workspace 字节数和 executor，再调用 `aclnnCsaSpmdTndPto` 提交到 stream。参数调用次序见 [aclnn_test/invoke.h](aclnn_test/invoke.h)，完整生命周期见 [main.cpp](aclnn_test/main.cpp)。读取结果前由调用者同步；workspace 和输入输出存储在执行完成前必须保持有效。

## 3. 57 项外部 Tensor

- `T` 是输入 token 容量，`B` 是请求容量；实际有效数量由 device metadata 表达。
- `Nm/Ni` 分别是主压缩/Indexer 压缩槽位行数，对应 cos、sin、slots 必须一致。
- `R*` 是对应缓存或 state 的行数，`W*` 是其行宽；`C*` 是对应页表列数。各符号独立，不能把所有动态轴统一当成 T。

## 4. 描述符与数据约束

- 采用 NZ2、固定模型维度和 24 AIC / 48 AIV。七项 NZ 权重为 `wq_a/wq_b/wo_a/wo_b/wkv/idx_wq_b/weights_proj`，上游 NPU 准备层检查格式 29。`wkv` 和 `weights_proj` 保持 Native 的 `[N,K]` 方向，在核内以 `b_trans=True` 消费；准备权重时须传实际 SPMD 根入口，不能继续沿用旧 ND 转置副本。
- 所有 Tensor 须在同一设备，满足连续描述符；dtype、rank 和固定维度按表检查。Meta 不检查实际设备数据值。
- `T/B` 为正；T 轴、B 轴、`B+1` bounds 和 Nm/Ni 的相互关系由 [contract.h](include/contract.h) 检查。
- `Wms >= 8192` 且为 16 的倍数；`Wis >= 1040` 且为 16 的倍数；`Wic >= 4160` 且为 64 的倍数。Indexer cache 是 INT8 物理页，包含 key 与 scale 区，不能只保留 4096 字节 key。
- 原默认选择器要求 query/history 上界有效，`T <= B × max_query_tokens`，`max_seq_len // 4` 在 `[2048,262144]`。这些是策略准备约束；Host 接收 key，不重新运行 Python 选择器。
- 页表、槽位、位置、每请求长度和 query bounds 的数值须满足原算法语义，且不越过对应缓存容量。Host/Meta 的描述符检查不能证明这些设备值合法；当前不会为选档读回 metadata。

本工程保持已知输入绑定的别名关系，不提供任意输入输出重叠的支持保证。设备已测范围和未测边界单列于 [DYNAMIC_SHAPES.md](DYNAMIC_SHAPES.md)，不能把 62 策略可编译理解为所有输入已验收。

## 5. Tiling key、内部 workspace 与所有权

`select_policy → 完整 constexpr 匹配 → variant 0–61` 在 Python 准备层完成。Host 读取实际描述符，调用 `Layout0…Layout61` 后设置 tiling key；纯 C++ 调用者需自行提供符合原选择策略的 key。编号对应编译策略，不固定 T/B。

```text
ACLNN workspace = Layout<key>(实际描述符).workspaceBytes
               + PlatformAscendC::GetLibApiWorkSpaceSize()
```

当前平台系统区为 16 MiB；用户区由实际 T/B 与策略计算，并按 512 字节对齐。内部 70 项申请和 6 项别名由生成布局描述，MIX 入口从外部指针与 workspace 偏移还原 133 个参数，并传递 28 个运行时标量。缓存/state 仍属于外部输入输出，不因转换 ACLNN 而复制进临时区。

[workspace.h](include/workspace.h) 实现申请、对齐、reshape/view 和溢出检查；[layout_generated.h](include/layout_generated.h) 是各策略的展开结果。生成核保留自身清零与同步逻辑；Python 不分配或持有内部 signal/scratch。申请量及各策略代表值见 [WORKSPACE.md](WORKSPACE.md)，不可将代表值当成固定值或上限。

## 6. 连续调用、rebind 与 graph replay

准备、库加载和 Top-K 存储分配须在 capture 前完成。连续调用会继续修改 cache/state；对照验证时两侧必须从相同初始状态开始。

`prepared.rebind(native_inputs)` 只支持相同 shape、stride、dtype、device 的根参数替换，不重新选择策略。它影响后续普通调用，不能修改已经捕获的图所保存的旧地址。

replay 要求捕获所用地址和容量保持有效；允许在同址修改 metadata 内容，但仍须满足所选策略的上界及数据合同。改变 T/B 等容量或需要不同策略时，应新建 PreparedAclnnCSA 并重新 capture；替换输入地址后也需重新 capture 才能让图使用新地址。

新版五个代表场景与 Python PTO 的接入一致性不等于独立数学 golden 已通过。旧基线 36 场景、10 项同址更新和 4 步连续状态仅保留历史身份，本轮未全量重测。精度结论、原始报告和计时范围分别见 [验证清单](dynamic_validation_results.json)、[适配日志](ADAPTATION_LOG.md)及[性能说明](PERFORMANCE.md)。
