# 单 SPMD TND：接口签名与参数传递

本文解释当前 Python 接口如何把模型数据交给 `decode_csa_spmd()`，作为阅读代码和设计 ACLNN 接口的起点。
版本与实施范围见 [接入计划](接入计划.md)。以下均指 `deepseek_v4_flash_csa_spmd_tnd`，尚未定义新的 ACLNN 签名。

## 1. 先看一次调用

```text
模型侧：权重、hidden、位置、metadata、KV cache/state、输出空间
  ↓ bind_native_inputs(...)
native：按名称组织的 Tensor 字典
  ↓ PreparedDynamicCSA(native, ...) 首次准备；后续可 rebind(native)
prepared.buffers：外部 Tensor + 内部工作区 + 同存储视图
  ↓ prepared(config=...)
decode_csa_spmd(**buffers, **policy.constexprs(), config=...)
  ↓ 单 SPMD 执行整条 CSA
写入 output、Top-K、cache/state；prepared 返回原来的 x_out
```

[`service.py`](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/service.py) 负责模型侧组织与复用。
独立测试则直接构造 `native` 后创建 `PreparedDynamicCSA`，跳过模型服务和 `bind_native_inputs()`。

| 接口 | 输入 | 结果 |
| --- | --- | --- |
| `bind_native_inputs(...)` | 模型已有对象和 Tensor | 返回 `native` 字典 |
| `PreparedDynamicCSA(...)` | `native`、长度上界、可选策略和分配器 | 创建准备对象，分配内部工作区 |
| `prepared.rebind(native)` | 新一轮、描述符相同的根 Tensor | 更新绑定，返回 `None` |
| `prepared(config=...)` | 可选编译配置 | 提交执行，返回 `native["x_out"]` |
| `decode_csa_spmd(...)` | 展开的 Tensor 和编译期策略参数 | 原地写入结果，并在源码中返回更新后的 Tensor 元组 |

这里的“描述符”指 shape、stride、dtype、device 等属性，不是 Tensor 中的数值。
`runtime_abi.py` 提供维度符号和同步阶段编号，**不是调用链里执行的一层函数**。

## 2. `bind_native_inputs`：把模型对象整理成字典

定义：[native_adapter.py，第 37 行](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/native_adapter.py#L37)。
实际调用：[service.py，第 312 行](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/service.py#L312)，位于 `CSAServiceRuntime.__call__()` 内；这里可以看到每个实参从哪里传入。
这里的 **bind（绑定）** 是把模型已有的 Tensor，放到下层约定的参数名下，必要时建立同一块内存的视图。
模型侧的数据散在权重字典、请求 metadata 和各组 cache/state 中；下层 binding 需要统一的 `native` 字典，
所以由这个函数完成整理和基本检查，让核入口无需理解模型对象。

```python
# 实际映射中的三个例子：保存 Tensor 引用，不复制数据
native["x_hc"] = hidden
native["x_out"] = output
native["cmp_query_start_loc"] = groups["compressed"][0].decode.query_start_loc
```

它返回的是一个普通字典，不建立自动跟随关系：同一 Tensor 的内容更新后，下层能读到更新；
若调用方换成另一块 Tensor，旧字典不会自动跟着换，需要重新整理并交给 `prepared.rebind()`。
这个函数本身不执行 CSA，也不是把数据从 CPU 搬到 NPU。

以下保留实际参数名，省略类型注解；`*` 后面的参数必须按名称传入。

```python
bind_native_inputs(
    weights, hidden, positions, groups,
    *, layer_name, compact_metadata, output, topk, topk_scores,
) -> dict[str, torch.Tensor]
```

| 参数 | 调用方需要提供什么 |
| --- | --- |
| `weights` | 已加载、已转换到所需布局的权重字典，包括量化 scale、归一化权重等 |
| `hidden` | 连续 BF16 `[T, 4, 4096]`，即 mHC 的 4 路残差输入 |
| `positions` | INT64 `[T]`，各 token 的位置 |
| `groups` | 五组 metadata 与 cache/state Tensor，结构见下表 |
| `layer_name` | 当前层名称，用来从 metadata 选择该层的 RoPE 数据 |
| `compact_metadata` | `compressed`、`indexer` 各自的 `(cos, sin, slots)` |
| `output` | 调用方预分配，shape/dtype 与 `hidden` 相同 |
| `topk` | Indexer 选出的索引，服务预分配 INT32 `[T, 512]`；供 CSA 内部后续 Attention 使用 |
| `topk_scores` | 对应的 Indexer 分数，服务预分配 FP32 `[T, 512]`；保留作检查，不是最终 Attention 权重 |

`T` 是分配的 token 容量，可能含 padding，不等于有效 token 数。

`groups[name]` 的结构为 `(metadata, cache_views)`，函数从 `metadata.decode` 读取请求描述：

| `groups` 的键 | `cache_views` 内容 | 用途 |
| --- | --- | --- |
| `swa` | `(swa_cache,)` | 原始滑窗 KV |
| `compressed` | `(compressed_cache,)` | 主压缩 KV |
| `state` | `(compress_state,)` | 主压缩跨调用状态 |
| `indexer` | `(indexer_key, indexer_scale)` | Indexer 的量化 key 与 scale 存储 |
| `indexer_state` | `(indexer_state,)` | Indexer 压缩状态 |

各组 metadata 提供请求边界、序列长度、页表等；部分组还提供 slots 和 RoPE 数据。
其中请求边界是 INT32 `[B+1]`，序列长度是 INT32 `[B]`，`B` 是请求槽容量，可能包含失活槽位。

**这一步只检查和绑定：**先复制权重字典，再加入本轮输入、输出、cache/state 和 metadata 的 Tensor 引用或视图。
它不分配业务输出，不把设备上的长度读回 CPU，也不负责把原始 checkpoint 权重转换成 NZ。

## 3. `PreparedDynamicCSA`：准备、换绑、执行是三件事

源码：[binding.py](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/binding.py)。

### 首次准备

```python
prepared = PreparedDynamicCSA(
    native,
    max_query_tokens=6,
    max_seq_len=max_seq_len,
    allocator=None,
    policy=None,
)
```

| 参数 | 含义 |
| --- | --- |
| `native` | 上一步的 Tensor 字典；独立测试也可直接构造同样的字典 |
| `max_query_tokens` | 每个有效请求的 query 数量上界，不是所有请求的实际长度 |
| `max_seq_len` | Host 已知的总序列长度上界，用于策略选择；实际每请求长度仍由设备 Tensor 给出 |
| `allocator` | 可选 `allocator(name, shape, dtype, device) → Tensor`；测试用它在工作区两端加保护区 |
| `policy` | 可选策略对象；省略时根据容量和上界调用 `select_policy()` |

构造过程依次完成：检查输入 → 选择策略 → 改名/建立视图 → 分配中间工作区 → 初始化 `signal`。
当前要求 `VLLM_ASCEND_ENABLE_NZ=2`，并检查 `wq_a/wq_b/wo_a/wo_b` 的 NZ 格式。

准备对象中最值得区分的三个成员：

| 成员 | 内容 |
| --- | --- |
| `native` | 保留上层命名的外部 Tensor 引用 |
| `buffers` | 按核入口参数名组织的全部 Tensor，包括外部数据和内部工作区 |
| `allocations` | 此对象新分配的工作区；是 `buffers` 的一部分，不包含全部外部权重/cache |

### 后续换绑

```python
prepared.rebind(next_native)  # 返回 None
```

只替换外部 Tensor 绑定，并重新建立相应视图；要求 shape、stride、dtype、device 与原来一致。
它不重新分配内部工作区，不清零 `signal`，也不重新选择策略。
容量或策略变化需要另一准备对象，模型服务负责按描述符和策略选择对象。

**换绑与图重放要分开理解：**`rebind()` 可以在正常 Python 调用时替换地址；已经捕获的图不会因此自动改用新地址。
replay 跳过 Python，必须使用符合图约定的地址并更新其中的数据。

### 提交执行

```python
result = prepared(config=compile_options)
```

内部关键代码是：

```python
options = {} if config is None else {"config": config}
decode_csa_spmd(**self.buffers, **self.policy.constexprs(), **options)
return self.native["x_out"]
```

`result` 就是调用方原先提供的 `output` Tensor，不是另分配一份输出。
**整条 CSA 的业务输出是 `output`，不是三个输出。** `topk/topk_scores` 是 Indexer 阶段结果，
当前实现由服务分配并作为可写参数传入，不代表模型需要额外接收两个结果。
`topk_indices` 随后传给 `attention_slot_plan_stage()`，决定后续 Attention 访问哪些候选；
该阶段不接收 `topk_scores`，后者保留供测试比对，也不是 Attention 的 softmax 权重。
各组 cache/state 则是原地更新、供后续调用继续使用的状态。

## 4. 同一个参数，如何从上层到核入口

下表覆盖主要外部数据。完整直接改名表在 `binding.py` 的 `direct` 中；视图转换紧接其后。

| 上层数据 | `native` 字典键 | 核入口参数 | 变化 |
| --- | --- | --- | --- |
| `hidden` | `x_hc` | `x` | `[T,4,4096] → [T,16384]` 同存储视图 |
| `output` | `x_out` | `output` | 同上，核写入的就是调用方输出空间 |
| `positions` | `position_ids` | `positions` | 保留原 Tensor |
| HC 权重 | `hc_attn_fn/scale/base` | `hc_fn/scale/base` | 对应改名；base 另有 `[1,24]` 视图 `hc_base_2d` |
| 主压缩请求边界/长度 | `cmp_query_start_loc` / `cmp_seq_lens` | `main_bounds` / `main_lengths` | 保留原 Tensor |
| Indexer 请求边界/长度 | `idx_query_start_loc` / `kv_seq_lens` | `idx_bounds` / `idx_lengths` | 保留原 Tensor，不能与主压缩组按 shape 相同而合并 |
| 原始 KV cache | `kv_cache` | `cache_rows` | 展平为 `[-1,512]` 视图，可写 |
| 压缩 KV cache | `cmp_kv` | `main_cache` | 展平为 `[-1,512]` 视图，可写 |
| Indexer key/scale 存储 | `idx_native_kv_cache` | `idx_cache` | 适配层暴露页存储，binding 保留该 Tensor，可写 |
| 主/Indexer 压缩状态 | `compress_state` / `inner_compress_state` | `main_state` / `idx_state` | 适配层建立物理页视图，binding 对应改名，可写 |
| 三组 KV 页表 | `ori/cmp/idx_block_table` | `original/compressed/indexer_table` | 对应改名，只读映射信息 |
| 原始 KV 写入位置 | `ori_slot_mapping` | `native_slots` | INT32 `[T,2]`，告诉核写入哪个页、哪一行 |
| `topk` / `topk_scores` | `idx_topk` / `idx_topk_scores` | `topk_indices` / `topk_scores` | 原地写入 |

例如 `hidden → native["x_hc"] → buffers["x"]`，三处名称不同，但底层数据没有复制。
内部也有这种关系：`q_heads` 是 `q_flat` 的另一个视图，不能因为传入两个名字就当成两块独立内存。

## 5. `decode_csa_spmd` 的长签名怎么读

源码：[entry.py](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/entry.py)。
不必先记住全部参数，先按下面几类理解：

| 类别 | 代表参数 | 谁准备 |
| --- | --- | --- |
| 输入与权重 | `x`、`hc_fn`、`wq_a`、`wq_b`、`wo_a`、`wo_b` | 调用方提供，binding 绑定 |
| 请求与访存信息 | `positions`、`main_bounds`、`idx_lengths`、各组 table/slots | 调用方提供设备 Tensor |
| 业务输出与持久状态 | `output`、`cache_rows`、`main_state`、`idx_cache` | 调用方持有，核原地更新 |
| Indexer 阶段结果 | `topk_indices`、`topk_scores` | 当前由服务预分配，供内部计算或测试检查 |
| 内部中间结果 | `normed`、`qa`、`q_flat`、`score_arena`、`kv_ring` | binding 按容量分配 |
| 同步相关 | `signal`、`ffts` | binding 分配；初始化和使用还涉及 runtime |
| 编译期策略 | `QUERY_GROUP`、`QK_PANEL`、`BALANCED` 等 | `policy.constexprs()` 返回 |

以下是实际签名中的代表性声明（片段，不是完整可调用函数）：

```python
x: pl.Tensor[[T, 16384], pl.BF16]
main_lengths: pl.Tensor[[B], pl.INT32]
output: pl.InOut[pl.Tensor[[T, 16384], pl.BF16]]
signal: pl.InOut[pl.Tensor[[WORDS], pl.INT32]]
QUERY_GROUP: pl.constexpr
```

- `pl.Tensor`：说明 Tensor 的 shape、dtype，有些权重还指定布局。
- `pl.InOut[...]`：标记可被核更新的参数。输出、cache 和临时结果都可能使用它，**不能仅靠这个标记判断内存归谁、保留多久**。
- `pl.constexpr`：编译期确定的策略，例如每组最多处理几个 query；不是设备上每个请求的真实长度。
- `config`：交给 `@pl.jit` 包装层的编译选项，不是函数体声明的业务 Tensor 或策略参数。

`decode_csa_spmd()` 源码返回多个更新后的 Tensor，binding 没有接收这个元组；它依赖传入缓冲区的原地写入，再返回外部 `x_out`。

## 6. `runtime_abi.py` 帮助解释什么

源码：[runtime_abi.py](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/runtime_abi.py)。
这里的 ABI 可以先理解为各段核代码共同遵守的参数和同步约定。

| 内容 | 阅读时的含义 |
| --- | --- |
| `T`、`B` 等 `pl.dynamic(...)` | 签名中的维度符号，对应传入 Tensor 的容量；并非有效 token/请求数 |
| `P16`、`QR_ROWS` 等 | 中间工作区的维度符号；实际分配大小由 binding 计算 |
| `GROUPS=24`、`VECTORS=48` | 核组与 AIV 数量约定，不是 batch 大小 |
| `PHASE_*`、`PHASE_COUNT` | 同步阶段编号及数量，用于解释 `signal` |

例如 binding 把 `P16` 对应空间分配为 `ceil(T/16)*16` 行；仅看维度声明看不到这个分配公式。
请求实际长度则保存在 `main_lengths/idx_lengths` 等设备 Tensor 中，由核在执行时读取。

读完接口后，ACLNN 设计要继续回答的是：**哪些外部 Tensor 保留为入参，哪些中间结果放入 workspace，哪些状态需要跨调用持有。**
当前 Python 核入口包含这些不同角色，不能直接把长签名逐项照搬为最终用户接口。
