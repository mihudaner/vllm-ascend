## 目标与基线

参照 HC-pre 工程，交付可独立编译、安装、调用和验证的 CSA ACLNN 示例，并保持原 Python 的动态 shape 策略与计算语义。

- 算法基线：`c346573ab3313fcc71cd58756acd129f34755439`。范围为 HC-pre → 输入 RMSNorm → CSA → HC-post，不含 FFN/MoE。
- 工作仓：`/data00/wangkai/aclnnWorkspace/vllm-ascend`，分支 `csa_spmd_tnd_aclnn`。Python PTO 对照与 ACLNN 使用同一仓库。
- 编译、安装、输入快照、设备报告放在仓外 `aclnnWorkspace`；公共 shared-toolchain 固定，未另选 SDK。
- 当前是独立单算子工程；尚未替换 vLLM 模型服务中的 CSA 调用。

## 实际适配路线

```text
原 Python 绑定/策略选择
  → PreparedAclnnCSA：完整 policy 匹配 tiling key
  → Torch 扩展 → ACLNN 两阶段接口
  → Host 按实际描述符计算 workspace 与运行时标量
  → MIX 入口还原指针 → PyPTO 生成的单 SPMD TND 核
```

纯 C++ runner 可直接调用同一 ACLNN 接口。构建、安装和运行命令统一见 [README](README.md)，本计划不重复维护命令及参数清单。

## 本次适配的关键决定

1. 取消早期八场景 T/B 白名单，复用原 Python `select_policy`；实际 T/B、缓存和页表描述符进入 Host 布局计算。此前静态版本不再作为当前支持范围。
2. 延续 c346573 的内部工作区设计。Python 仅绑定外部输入输出；ACLNN Host 计算内部空间，MIX 入口还原生成核所需指针，保持生成核初始化与同步行为。
3. 保留缓存/state 原地更新与诊断输出。Torch/ACLNN 的 57 项外部 Tensor 和生成包装的 133 个指针属于不同接口层，详细对应见参数说明。
4. 将“与原 PTO 一致”和“独立数学 golden 通过”分开验收；不放宽数学阈值，也不把 CPU/编译覆盖写成设备覆盖。
