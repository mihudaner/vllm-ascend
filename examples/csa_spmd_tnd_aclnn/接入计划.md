## 1. 从模型到算子的当前调用链

### 模型入口与实现选择

以下是启用 PTO CSA 模型后的路径。初始化时，`prepare_csa_model()` 根据 `variant.py` 选择实现、准备权重和 runtime；`install_csa_forward()` 替换压缩比为 4 的层的 forward。

```text
models/deepseek_v4.py
AscendDeepseekV4ForCausalLM.forward()
  └─ DeepseekV4Model.forward()
      └─ 遍历 decoder layer，调用 layer(...)
          └─ models/pypto_deepseek_v4.py：csa_layer_forward()
              ├─ torch.ops.vllm.dsv4_csa_forward(...)
              │   └─ ops/dsv4_csa.py：dsv4_csa_forward()
              │       ├─ 空调用：按 TND runtime 规则处理后返回
              │       ├─ runtime 不存在或 eligible() 不满足
              │       │   └─ _native_attention_half()：Native 回退
              │       └─ 满足 PTO 条件
              │           └─ 所选包的 CSAServiceRuntime.__call__()
              └─ FFN / MoE 半边：继续原来的实现
```

PTO 接管的范围是 **HC-pre → input RMSNorm → CSA → HC-post**，输入、输出均为 mHC 残差流；不是只替换 QK/softmax/AV，也没有把 FFN 一起融合。
Native 回退覆盖同样的 Attention 半边。

源码入口：[模型接入](../../vllm_ascend/models/pypto_deepseek_v4.py)、[custom op 与回退](../../vllm_ascend/ops/dsv4_csa.py)、[实现选择](../../vllm_ascend/ops/pypto/variant.py)。

### 进入 TND 单 SPMD 后

以下文件均位于 `deepseek_v4_flash_csa_spmd_tnd/`：

```text
service.py：CSAServiceRuntime.__call__()
  │  取得本轮 metadata、KV cache/state，准备 Top-K 等输出
  │
  ├─ native_adapter.py：bind_native_inputs()
  │   把模型已有的权重、输入、页表、slots、cache/state 绑定为算子参数
  │
  └─ binding.py：PreparedDynamicCSA
      │  首次准备工作区；同描述符后续调用通过 rebind() 更新根 Tensor 绑定
      │
      └─ PreparedDynamicCSA.__call__()
          └─ entry.py：decode_csa_spmd()                 @pl.jit
              └─ with pl.spmd(GROUPS=24, sync_start=True)
                  └─ _csa_core_group()                  @pl.jit.inline
                      └─ with pl.cluster("dynamic_csa_full")
                          ├─ cube_schedule.py：cube_schedule()
                          │   AIC：矩阵乘等阶段
                          └─ vector_schedule.py：vector_schedule()
                              AIV：归约、量化、规划、搬运等阶段
```

两种角色协同完成整链，各阶段数学位于相应的 `*_stages.py`，核间依赖由 `phase_sync.py`、`signals.py` 等实现。
这里描述的是 Python 准备和提交路径；图捕获后的 replay 不会重新执行整条 Python 调用链。

源码入口：[service.py](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/service.py)、[绑定与工作区](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/binding.py)、[SPMD 入口](../../vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd_tnd/entry.py)。

### 原调用栈哪些部分还适用

| 选择的实现 | runtime 后面的调用路径 |
| --- | --- |
| 原 `deepseek_v4_flash_csa` | `NativeCSACall / HBGNativeCSACall → self.ops.attention(...) → decode_csa_tp1_layer_test / decode_csa_tp1_layer_hbg`；原描述适用于这一路 |
| `deepseek_v4_flash_csa_spmd_tnd` | `bind_native_inputs → PreparedDynamicCSA → decode_csa_spmd`；当前单 SPMD 应看这一路 |
| `deepseek_v4_flash_csa_tnd` | 复用 TND 服务框架，但使用自己的 binding 和 `decode_csa_tnd` 多任务入口 |

独立复现则由 `tests/pypto_test/csa_torch_repro/run.py` 构造输入、创建 `PreparedDynamicCSA` 并调用，跳过模型和服务入口。它适合作为 ACLNN 初期对照测试的输入来源。

## 2. HC-pre 的 ACLNN 工程能借鉴什么

已有示例位于原 HC-pre 工作区的 `vllm-ascend/examples/hc_pre_pto_aclnn/`，当前仓库尚无该目录。它采用以下结构：

```text
Torch 扩展
  → aclnnHcPrePtoBnnGetWorkspaceSize / aclnnHcPrePtoBnn
    → CANN MIX 核入口
      → 离线生成的 PTO AIC / AIV C++ 函数
```

可借鉴的是“离线生成核代码，再封装为 CANN 算子”的工程方式。CSA 的接口和工作区需要根据当前实现重新梳理。

| HC-pre 工程位置 | CSA 对应来源 | 初步需要做什么 |
| --- | --- | --- |
| `generated/` | `entry.py`、`cube_schedule.py`、`vector_schedule.py` | 导出所选策略下的 AIC/AIV 生成代码，核对是否依赖 PyPTO/Simpler 的派发参数与辅助接口 |
| `include/contract.h` | `runtime_abi.py`、`binding.py`、`policy.py` | 明确外部参数、动态维度、布局、策略及工作区偏移 |
| `op_host/` | 当前 binding 与策略选择 | 注册输入输出，检查描述符，选择编译分支并计算工作区；实际请求边界仍由设备读取 |
| `op_kernel/` | 当前 MIX 入口与同步代码 | 衔接 AIC/AIV 函数，适配核组编号、参数和同步所需存储 |
| `torch/binding.cpp` | 当前 `PreparedDynamicCSA` 的提交位置 | 提供 Torch → ACLNN 调用，声明输出及 cache/state 的原地修改关系 |
| `tests/` | 独立 PyTorch 复现入口 | 用相同输入和初态比较 PyPTO 与 ACLNN 的输出、状态和图重放 |

目前仍需验证 CSA 的生成代码能否像 HC-pre 一样脱离 Simpler 直接运行，不能仅凭“整链只有一个 SPMD”就认定已经满足直接封装条件。

## 3. 接入时先关注这几个差异

| 关注点 | 当前 CSA 的情况 | ACLNN 接入时的处理方向 |
| --- | --- | --- |
| 参数不只是输入和权重 | 还有请求边界、长度、位置、页表、slots、压缩元数据及多组 cache/state | 从 `bind_native_inputs()` 梳理外部接口；保持请求与 KV 映射的一致性 |
| 内部 Tensor 数量多 | `PreparedDynamicCSA` 分配中间结果、计划表及同步区，并建立存储别名 | 区分真正的外部输入、持久状态和临时 workspace，保留 shape/stride、NZ 布局和对齐要求 |
| 算子会修改状态 | 除输出外，还写入 KV cache、压缩状态等 | 保留原地更新语义，测试不能只比较最后的输出 Tensor |
| 同步区有生命周期 | 当前 signal 在准备时初始化，后续调用沿用代际；不能在每次 replay 随意清零 | 明确同步区的分配、初始化与跨调用复用方式，不能直接当作内容任意的临时 workspace |
| 核间协作依赖运行条件 | 当前使用 24 AIC + 48 AIV、启动同步及核间通知/等待 | 核对 CANN MIX 启动能否满足这些条件，保留核编号、发布可见性和等待语义 |
| graph replay 复用已捕获地址 | 当前服务检查描述符、地址、容量和策略 | 初期固定容量与策略，在同址更新设备元数据的条件下验证 replay，再扩大支持范围 |

#### 1.2 外部接口：哪些参数由调用方提供

**本轮结论：外部接口应接收已有业务数据，不应把 PyPTO 入口的所有 Tensor 都交给调用方准备。**
已沿 `native_adapter.py → binding.py → runtime_abi.py → entry.py` 核对；这些文件及 `policy.py` 与 1.1 选用的冻结参考组一致。

入口共有 **130 个 Tensor 参数 + 21 个编译期参数**。其中 57 个 Tensor 参数来自 **56 个不同的外部根参数**（`hc_base` 和 `hc_base_2d` 使用同一份数据）；其余是 70 个内部独立分配和 3 个内部派生视图。
这里的“56 个根参数”指语义接口数量，不表示它们在所有场景下都必须占用 56 块独立存储。

```text
调用方准备：输入 + 已转换权重 + 元数据 + KV/cache state
    ↓ Torch 包装层检查描述符、建立同存储视图、准备输出
首版 ACLNN 业务接口：48 个只读根参数 + 5 个原地更新根参数 + 3 个输出
    ↓ 核包装层补上内部工作区、派生视图和固定策略
decode_csa_spmd 对应的 AIC / AIV 生成函数
```

以上是**首版接口草案**，不是已注册的 ACLNN 函数签名。同步状态如何传入、workspace 如何分区留在 1.3；CANN 注册方式和生成核 ABI 仍需阶段二验证。

##### A. 参数表的读法与首轮规格

- 下表左列使用当前 `native` 字典中的根参数名，右列给出 kernel 参数名；不是原始 checkpoint 的名称。
- `T` 是 token 容量，`B` 是请求槽容量；首轮 `T=64、B=17`，其中有效 token 为 55、活动请求为 16。不能按 `64/17` 推导 query 长度。
- `C_m/C_i` 是主分支/Indexer 的紧凑元数据容量，slots 的行容量分别记为 `S_m/S_i`；首轮均为 30，但不要求一般场景始终相等，也不能替换成有效压缩条数。
- `P_*` 表示各组物理页数，`E_*` 表示每页 FP32 元素数，`L_*` 表示页表每行实际存储列数；不同组分别取值。
- **ND** 表示连续描述符：一维 stride 为 `(1)`，二维 `[M,N]` 为 `(N,1)`，三维按行连续。**NZ** 的 shape 是逻辑 shape，物理字节顺序不能用普通 ND stride 解释。
- 所有 Tensor 在同一 NPU。现有代码未为每个业务根参数声明独立的基地址对齐数值，不能擅自写成“全部 512B 对齐”；首版复用既有 NPU 分配与合法视图。已明确的页跨度、共享区偏移列在下文，生成核更严格的地址要求待导出后核验。`signal` 的 512B 对齐属于内部状态，归入 1.3。

##### B. 本轮输入与输出：7 个根参数

| 调用方根参数 → kernel 参数 | 用途 | shape / dtype | 布局、方向与来源 |
| --- | --- | --- | --- |
| `x_hc → x` | 四路 mHC 残差输入 | `[T,4,4096]` BF16 → `[T,16384]` | 连续 ND，只读；上层模型或测试输入，同存储展平 |
| `position_ids → positions` | 每个 token 在所属请求中的位置 | `[T]` INT64 | ND，只读；调度元数据，不能用 token 行号代替 |
| `freqs_cos / freqs_sin → rope_cos / rope_sin` | 本轮 Query/KV 的 RoPE 数据 | 各 `[T,64]` FP32 | ND，只读；当前服务取 compressed 组的逐层 RoPE 视图 |
| `x_out → output` | 完整 HC-pre→CSA→HC-post 输出 | `[T,4,4096]` BF16 → `[T,16384]` | 连续 ND，写；调用方或 Torch 层预分配，与 `x_hc` 分开 |
| `idx_topk → topk_indices` | 每个 query 选中的压缩候选编号 | `[T,512]` INT32 | ND，写；首版保留外部输出用于一致性验证 |
| `idx_topk_scores → topk_scores` | 对应候选分数 | `[T,512]` FP32 | ND，写；调用方或 Torch 层预分配 |

后三项在 PyPTO 签名里标为 `InOut`，业务上是结果缓冲，不是历史状态。首版仍沿用测试入口的输出初值约定（`x_out=0、idx_topk=-1、idx_topk_scores=0`），不以“写输出”推断所有 padding 行都一定被覆盖；初始化应由包装层的设备操作完成，是否必须重复初始化留给连续调用验收确认。

| 调用方根参数 → kernel 参数 | 用途与来源 | shape / dtype | 布局 |
| --- | --- | --- | --- |
| `hc_attn_fn → hc_fn` | layer 的 HC 控制量投影 | `[24,16384]` FP32 | ND |
| `hc_attn_scale → hc_scale` | HC 三组缩放 | `[3]` FP32 | ND |
| `hc_attn_base → hc_base / hc_base_2d` | HC 偏置；两种视图同一根参数 | `[24]` / `[1,24]` FP32 | ND，同址 |
| `attn_norm_w → norm_w` | input RMSNorm 权重 | `[4096]` BF16 | ND |
| `wq_a → wq_a` | Query 降维投影 | `[1024,4096]` BF16 | **NZ，format 29** |
| `gamma_cq → gamma_cq` | 低维 Query RMSNorm | `[1024]` BF16 | ND |
| `wq_b → wq_b` | Query 升维量化权重 | `[1024,32768]` INT8 | **NZ，format 29** |
| `wq_b_scale → wq_b_scale` | Q 升维逐输出通道反量化 scale | `[32768]` FP32 | ND |
| `wkv → wkv` | 共享 KV 投影；由模型矩阵转成此方向 | `[4096,512]` BF16 | ND |
| `gamma_ckv → gamma_ckv` | 共享 KV RMSNorm | `[512]` BF16 | ND |
| `cmp_wkv / cmp_wgate → main_wkv / main_wgate` | 主 Compressor 的 value/score 投影 | 各 `[1024,4096]` BF16 | ND |
| `cmp_ape → main_ape` | 主 Compressor 位置偏置 | `[4,1024]` FP32 | ND |
| `cmp_norm_w → main_gamma` | 主压缩结果 RMSNorm | `[512]` BF16 | ND |
| `inner_wkv / inner_wgate → idx_wkv / idx_wgate` | Indexer Compressor 的 value/score 投影 | 各 `[256,4096]` BF16 | ND |
| `inner_ape → idx_ape` | Indexer Compressor 位置偏置 | `[4,256]` FP32 | ND |
| `inner_norm_w → idx_gamma` | Indexer 压缩结果 RMSNorm | `[128]` BF16 | ND |

| `attn_sink → attn_sink` | Attention 每个 head 的 sink | `[64]` FP32 → `[64,1]` | ND，同存储视图 |
| `wo_a → wo_a` | 8 组输出降维投影 | `[8,4096,1024]` BF16 | **NZ，format 29** |
| `wo_b → wo_b` | 输出升维量化权重 | `[8192,4096]` INT8 | **NZ，format 29** |

##### D. 请求、页表、slots 与压缩元数据：18 个只读根参数

这些数据由框架或独立测试准备，ACLNN 读取已有设备 Tensor。首版不把 Native 的 `compressor_metadata` 生产者融合进 CSA，也不要求 ACLNN 在 Host 上回读实际长度。

| 调用方根参数 → kernel 参数 | 用途 / 来源 | shape / dtype | 布局与关键约定 |
| --- | --- | --- | --- |
| `cmp_query_start_loc → main_bounds` | 主分支本轮请求前缀边界 | `[B+1]` INT32 | ND |
| `cmp_seq_lens → main_lengths` | 主分支包含本轮 query 的总长度 | `[B]` INT32 | ND |
| `idx_query_start_loc → idx_bounds` | Indexer 本轮请求前缀边界 | `[B+1]` INT32 | ND |
| `kv_seq_lens → idx_lengths` | Indexer 包含本轮 query 的总长度 | `[B]` INT32 | ND；名称虽为 kv，实际来自 Indexer 元数据 |
| `ori_block_table → original_table` | 原始窗口 KV 的请求→物理页映射 | `[B,L_o]` INT32 | 连续完整行，stride `(L_o,1)` |
| `cmp_block_table → compressed_table` | 主压缩 KV 页表 | `[B,L_c]` INT32 | 同上，使用本组列跨度 |
| `idx_block_table → indexer_table` | Indexer Key/Scale 页表 | `[B,L_i]` INT32 | 同上，使用本组列跨度 |
| `state_block_table → main_state_table` | 主 Compressor 历史 state 页表 | `[B,L_s]` INT32 | 同上 |
| `inner_state_block_table → idx_state_table` | Indexer Compressor 历史 state 页表 | `[B,L_is]` INT32 | 同上 |
| `ori_slot_mapping → native_slots` | 本轮原始 KV 的写入页号/页内位置 | `[T,2]` INT32 | ND；页内位置范围 0～31 |
| `state_slot_mapping → main_state_slots` | 主 Compressor state 写槽 | `[T,2]` INT32 | ND；state 每页 2 个位置 |
| `inner_state_slot_mapping → idx_state_slots` | Indexer Compressor state 写槽 | `[T,2]` INT32 | ND；state 每页 2 个位置 |
| `cmp_freqs_cos / cmp_freqs_sin → main_cos / main_sin` | 主分支本轮关闭压缩组的 RoPE | 各 `[C_m,64]` FP32 | ND；来自主分支 compact metadata |
| `cmp_slot_mapping → main_slots` | 主分支关闭压缩组的 KV 写槽 | `[S_m,2]` INT32 | ND；与主分支 compact 行次序一致 |
| `inner_freqs_cos / inner_freqs_sin → idx_cos / idx_sin` | Indexer 关闭压缩组的 RoPE | 各 `[C_i,64]` FP32 | ND；来自 Indexer compact metadata |
| `idx_slot_mapping → idx_slots` | Indexer 关闭压缩组的 Key/Scale 写槽 | `[S_i,2]` INT32 | ND；与 Indexer compact 行次序一致 |

主/Indexer 的 Q/L 和 compact 元数据必须分开传；即使某次值相同，也不能根据 shape 相同就合并。页表尾部有分配 padding 时，`table_storage()` 暴露完整物理行，不能用可见列数代替真实 stride。

`positions`、Q/L、页表和 slots 必须属于同一批请求、同一轮调用。活动请求的 `positions[t] = lengths[r] - (bounds[r+1]-bounds[r]) + t-bounds[r]`；dummy 请求以无效长度排除，相应写槽为负。合法写槽须满足唯一写入约定，不能依靠 kernel 自动消除跨请求写冲突。

##### E. KV cache / 压缩 state：5 个原地更新根参数

| 调用方根参数 → kernel 参数 | 内容和读写方向 | kernel 视图 / dtype | 物理布局及首轮实例 |
| --- | --- | --- | --- |
| `kv_cache → cache_rows` | 原始 KV；读历史并写本轮 slots | `[32×P_o,512]` BF16，读写 | 每页 32 行，每行 512；页间无额外间隙。首轮 `[4928,512]` |
| `cmp_kv → main_cache` | 主压缩 KV；读历史并写新关闭组 | `[32×P_c,512]` BF16，读写 | 同上。首轮 `[558176,512]` |
| `compress_state → main_state` | 主 Compressor 历史 value/score | `[P_s,E_s]` FP32，读写 | stride `(E_s,1)`，保留整页 padding。首轮 `[154,8192]` |
| `inner_compress_state → idx_state` | Indexer Compressor 历史 value/score | `[P_is,E_is]` FP32，读写 | stride `(E_is,1)`，保留整页 padding。首轮 `[154,1040]` |
| `idx_native_kv_cache → idx_cache` | Indexer INT8 Key + FP16 scale | `[P_i,page_bytes]` INT8 字节载体，读写 | `page_bytes≥4160` 且为 64 的倍数；首轮 `[17443,4160]` |

state 每个位置保存 `[value 的 2D, score 的 2D]`，每页 2 个位置；主分支 `D=512`，Indexer `D=128`。**有效内容宽度不等于物理页跨度**：首轮主 state 每页使用前 4096 个 FP32 元素、跨度为 8192；Indexer 使用前 1024 个、跨度为 1040。不能按有效元素数重新紧凑分配，然后仍传原来的页跨度。

Indexer 的两种数据实际共享一块存储：

```text
每页字节偏移：0                         4096            4160
             | 32×128 个 INT8 Key     | 32 个 FP16 scale |
             └──────── 同一个 idx_cache 根参数 ─────────┘
```

如果调用方给的是 Native Key 和 Scale 两个 view，Torch 层应验证共享存储、Scale 相对页首偏移 4096B、两者页 stride 一致，再建立 INT8 载体视图；不能把独立分配的两个 Tensor 直接当成这份接口。

##### F. 存储别名：哪些复用，哪些首版不允许

| 情况 | 当前事实 / 首版约定 |
| --- | --- |
| `x_hc→x`、`x_out→output`、cache/state 展平或整页视图 | 同一根参数的描述符转换，不复制业务数据；完整页和容量必须在实际 backing storage 内 |
| `hc_base` 与 `hc_base_2d` | 必须同址；ACLNN 业务接口只传一次 `hc_attn_base` |
| Indexer Key/Scale、入口内的 `idx_key0/idx_key64` | 同一根 cache 的必要别名；只向外暴露一个 `idx_native_kv_cache`，内部按协议建立读视图 |
| `q_heads`、`idx_query_rope_heads`、`idx_query_scale_heads` | 分别是内部 `q_flat`、`idx_query_rope`、`idx_query_scale` 的视图，不新增调用方参数 |
| 不同请求共享历史页 | 页表可以引用共享历史，但活动写槽必须满足唯一写入和生命周期约定；pool 读完后才能覆盖 state |
| `x_out` 与 `x_hc` 重叠，输出与 cache/state 重叠，workspace 与业务根参数重叠 | **首版接口不支持**；现有代码未给出这些跨根别名的完整正确性保证，不将 PyPTO 的 InOut 标注当作可任意别名的证明 |
| 主/Indexer 两份只读元数据共享存储 | 只有语义与布局都一致时才能复用；接口仍保留两个参数。可写 cache/state 各组首版要求互不重叠 |

包装层需显式声明 5 个 cache/state 根参数的原地修改关系；如果采用 `.out` 形式，还需声明三个输出的写入关系，避免 Torch 把它们当成无副作用的调用。

##### G. Host 属性与设备值的边界

| 内容 | 谁提供 / 读取 | 首版处理 |
| --- | --- | --- |
| `T、B`，页数、页跨度、表列数及 compact 容量 | 从 Tensor 描述符取得；Host 可读取 | 用于参数校验与 workspace 计算，不能替代有效 token/request 数 |
| `max_query_tokens、max_seq_len` | 调用方已有 Host 上界，传给 `select_policy()` | 首版固定为 1.1 用例对应策略，不新增设备回读来计算它们 |
| 21 个 `pl.constexpr` | `policy.constexprs()` 生成 | 固定进入首轮编译配置，不向用户暴露 21 个可任意组合的属性；后续多策略再设计策略选择接口 |
| NZ2、64 heads、8 输出组、C4、KV 页大小 32、state 页大小 2 | 模型/格式约束 | 首版固定并校验，不作为任意可变的模型属性 |
| Q/L、positions、各页表和 slots 的内容 | 调用方更新设备 Tensor，核读取 | 不转换成 Host 列表、不做逐请求 Host tiling |
| `num_reqs_actual、num_compressed_tokens、start_pos` 等前置元数据生产参数 | 框架或测试构造 compact 输入时使用 | 首版 CSA ACLNN 接收生产好的 compact Tensor；这些不是额外塞进主 kernel 的 Host 参数 |

`runtime_abi.py` 的动态维度由描述符解释；`GROUPS` 和各阶段编号是实现常量，调用代际与 phase signal 是执行状态。三者不能混成公开的“长度参数”。

##### H. 首版接口草案与包装层分工

首版先保持 56 个业务根参数的语义名称，C++ 侧按命名 Tensor 参数设计，Python 可以按组组织以方便调用；**分组不表示 CANN 已支持直接接收 Python 字典，也不提前承诺长参数列表已通过注册和编译**。

```text
调用方：
  本轮数据 / 已准备权重 / Q与L / 五套页表与slots / compact数据 / 五个cache-state
     ↓
Torch 包装层：
  检查 dtype、shape、device、布局与存储范围
  建立展平、整页、Indexer共享载体视图
  准备 output、topk_indices、topk_scores，声明原地更新
     ↓
ACLNN：
  GetWorkspaceSize / 执行入口（具体名称及签名待注册实现）
     ↓
核包装层：
  从统一 workspace / 独占状态中补齐内部参数，调用固定策略生成核
```

包装层可做的转换与校验：

1. **加载期转换**：将 checkpoint 权重转换为 B 表的方向、dtype、NZ/ND 格式，量化 offset 必须为零。复用已加载的匹配权重，不在 replay 内反复转置或打包。
2. **提交前的零拷贝转换**：按 `token_capacity_view()`、`physical_pages()`、`table_storage()`、`indexer_storage()` 的规则构造视图，检查 backing storage 覆盖范围；容量不足时报错，不偷偷分配补齐再声称同址 replay。
3. **参数校验**：所有输入同设备，精确核对 shape/dtype/格式、必要 stride 与可写区重叠；无法只靠描述符确认的请求顺序、slot 唯一性由调用方保证，并在测试里检查。
4. **输出与状态**：输出由调用方或包装层预分配；cache/state 保持原存储并原地更新。内部 `mixed、post、comb、q_heads、plan、ring、signal、ffts` 不要求业务调用方逐项构造；其中同步存储的独占生命周期留给 1.3 明确。
