# 62 策略的 workspace 申请量（2026-10-27）

本表及 workspace_sizes.json 保留 c346573 历史统计身份。1685da69 主要改变三张外部权重的布局和矩阵方向，内部申请逻辑未变；按用户要求，本轮不单独验证或重统计 workspace 大小，也不把下表标为新版实测。

workspace 不是每个 key 固定一个数值。以下是在 c346573 基线时直接在 CPU 调用当时的 `Layout0…Layout61` 计算 Host 申请量；未把 62 个策略全部运行一遍，也未实际申请这些容量。

```text
Host 申请量 = 用户 workspace(T, B, policy) + CANN 系统 workspace
当前 Ascend910_9382 / CANN 9.1 系统区 = 16,777,216 字节 = 16 MiB
```

系统区由本机 `PlatformAscendC::GetLibApiWorkSpaceSize()` 查询得到，核数核对为 24 AIC / 48 AIV。用户区每次分配按 512 字节对齐，最终也按 512 字节对齐。当前生成布局共 70 项内部分配，视图复用原存储。

当前内部申请量由 T、B 以及策略常量决定；cache 页数/页宽参与外部视图和设备标量，不复制整份 cache 到 workspace。表中不含权重、外部 KV cache、输入输出、Torch 缓存分配池或 graph pool。一次调用只使用所选策略的 workspace，不能把 62 行相加当作单次显存需求。并发或多图的存储生命周期另算。
