# HC_pre：优化 Native 与 PTO 的 ACLNN 普通调用对比（2026-10-14）

本文归档 2026-10-14 的历史测试，PTO 生成核基于 `f04320413`，不代表当前分支后续优化后的性能。本表 Native 使用优化版本 `HcPreBnn`，与 [开源 Native 与 PTO：Graph 重放对比](开源Native与PTO_Graph重放对比_20261013.md) 中的开源 `cann-recipes-infer` Native 不同。

- 直接查看双方数据：第 7 节的十四场景对照、补充用例和六档汇总。两侧均为 C++ ACLNN 普通调用，不开 replay，预热 5 次、正式 20 次取中位数。
- 第 1～6 节记录 Native 优化版本的环境、性能及精度；第 8～10 节是后续调用方式排查，独立列出，不能混为同一轮比较。

## 3. 性能统计口径

使用 msprof 的 `op_summary_*.csv`，筛选 OP Type=HcPreBnn，按设备任务开始时间排序。按 manifest 顺序每例对应 25 条任务，并核对每条任务的完整 Input Shapes；丢弃前 5 条后，对剩余 20 条计算中位数、均值、最小值、最大值。

主指标为 **Task Duration(us)**，不包含 CPU GetWorkspaceSize、分配内存、文件读取、H2D/D2H、golden 计算及精度比较。AIC/AIV 时间是 profiler 的另一种指标，不能代替 Task Duration；汇总见第 6 节 CSV。

原工程每例仅调用一次。此次只在原调用段外增加重复循环及环境变量读取：每轮重新查询 executor、准备 workspace、启动并同步；输入输出 tensor 保持同一组地址，最后一轮输出用于精度检查。算子包、golden 和精度标准均未改动。

## 8. 排查：为什么原 PR 的 Torch 测试比直接 C++ 调用慢

### 受控对照

2026-10-14，同一队列任务、物理设备 **8**，固定 T96 和同一套 PTO 二进制，对比调用与采集组合。此设备不同于前文全场景的设备 0；本节只在设备 8 内部作受控比较，不把与设备 0 的小幅差值解释成单一因素。

分别使用两组数据：测试生成的 T96 输入，以及原 PR 第 2 层模型权重与 seed=20262615 的 T96 输入。各组合均预热后统计 20 次中位数，所有指标均取 op_summary 的 Task Duration(us)。外部 msprof 采集时，从每个输入组取最后 20 次；Torch profiler 从 active=20 的窗口取 20 次。

| 调用方式 | 采集方式 | 合成输入 μs | PR 模型权重输入 μs |
| --- | --- | --- | --- |
| C++ 直接 ACLNN | 外部 msprof | 22.40 | 22.27 |
| Torch 普通调用（eager） | 外部 msprof | 22.72 | 22.67 |
| Torch NPU Graph 重放 | 外部 msprof | 26.07 | 27.57 |
| Torch NPU Graph 重放 | Torch profiler Level1（原 PR 的采集组合） | 30.47 | 30.69 |

### 当前能确定的结论

1. **输入分布不是本次大幅差距的主要解释。** C++ 直接调用下，两组数据都约 22 μs；并没有因换成模型权重就变成约 30 μs。
2. **Torch 普通调用本身没有带来此前 7～8 μs 的设备耗时差。** 相同外部采集方式下，Torch eager 与 C++ 均约 22～23 μs。这里没有测 Host/Python 总耗时。
3. **本次差异集中在图重放和采集组合。** 外部 msprof 下，Graph 比 eager 高；再换到原 PR 的 Torch profiler Level1 组合，测得约 30～31 μs。原 PR 的 29.40 μs 与这组结果处于相近范围。
4. **不是把精度比较或 GetWorkspaceSize 算进了 kernel 时长。** 两侧都读取 Task Duration，精度比较在计时任务外。也不是“3 次改成 20 次”即可解释：本次模型输入的 Torch profiler 前 3 次中位数为 30.84 μs，20 次为 30.69 μs。
5. **还不能把差值叫作固定 Graph 开销或固定 profiler 开销。** AIV 时间也随执行/采集组合变化，表明设备执行状态或采集扰动也参与其中；具体是缓存、调度、资源配置还是其他底层因素，尚未独立定位。各组合按顺序执行，不能将中位数相减视为严格可加的框架成本。

因此，原 PR 的数字是“图重放 + Torch profiler”的测试条件，本次 C++ 是另一套执行/采集条件。比较算子性能应统一这两项，而不是把原 PR 与本次数字的差全部归因于 ACLNN 或 Python。


## 9. 原版 PTO L1 同卡复测：为什么 ACLNN 比以前的 L1 还短

### 方法与范围

2026-10-14，物理设备 8，退出码 0。使用 **10-12 提交 f04320413804103fe31bedd5a2175b5021bcd91d 的原版 hc_pre.py**，没有加入我们的 DB 改动；源文件 SHA256 为 `ff90619b80ade29e673dd742d1c6fe42e237f5aa3ad2f6b4f300f80baec3df0c`。

固定 B=16、S=6、T=96、D=4096，BF16 输入，24 AIC + 48 AIV，Sinkhorn 20 次、epsilon=1e-6。分别复用第 8 节的合成输入和原 PR 模型权重输入。PyPTO `00d5ab9f`、Simpler `17e34245`，CANN 与前文一致。ACLNN 使用现有同一套二进制，没有重新编译。

- C++ ACLNN：预热 5 次，重复 20 次，外部 msprof 的 Task Duration 中位数。
- 原版 PTO：每个模式先普通调用预热 5 次，再对待测调用方式预热 5 次，采集 20 次 L1。分别测试普通调用、图重放、图重放同时开启原测试的 Torch profiler Level1。
- L1 按原脚本算法：**每次执行的全核最早 kernel 开始，到全核最晚 kernel 结束**；扣除各核 local_setup，不是单核时长，也不是 72 核耗时相加。包含核入口执行及核内等待，不包含整个 Python 调用或 GetWorkspaceSize。
- L1 每个采集窗口最多 3 次，累计 20 次；每次均核对 24 AIC + 48 AIV 的 72 条记录齐全。初次尝试连续采 20 次时图重放记录不全，该组排除，未用于下表。缺记录的底层原因未定位。
- 两组输入、三个 PTO 模式，mixed/post/comb 均通过精度检查；C++ 两组也通过测试工程检查。本节仅验证 T96，未重跑所有分档。

### 结果（20 次中位数，μs）

| 执行与采集方式 | 合成输入 | PR 模型权重输入 |
| --- | ---: | ---: |
| C++ ACLNN + 外部 msprof Task Duration | 22.82 | 22.64 |
| 原版 PTO 普通调用 + L1 | 22.24 | 22.33 |
| 原版 PTO 图重放 + L1 | 29.68 | 30.16 |

### 慢在哪里

下面拆解合成输入的 L1，每项也是 20 次的中位数。启动跨度是每次最晚核开始减最早核开始；最长 AIV 时间是每次 48 个 AIV 中最长的 kernel 区间，包含其内部同步等待。

| 指标 | 普通调用 | 图重放（未开 Torch profiler） |
| --- | ---: | ---: |
| 全核启动跨度 μs | 3.97 | 8.72 |
| 最长 AIV kernel 时间 μs | 21.63 | 27.96 |
| 最长 AIC kernel 时间 μs | 14.39 | 18.07 |

这几项区间互相重叠，不能相加。图重放既出现各核开始更分散，也出现 AIV kernel 区间变长；不能只解释为在计时范围外多了一次 launch。AIV 区间包含 FIFO/同步等待，因此也不能据此断言向量指令本身变慢。

### 结论

1. **原版 PTO 换成普通调用后也能跑到约 22 μs。** 与本次 C++ ACLNN 的约 23 μs 已处于相近范围，之前“封装后反而比原版 L1 快约 7 μs”的现象，主要来自拿普通调用和图重放作比较。
2. **此次原版 PTO 的差异在不开 Torch profiler 时也存在。** 因而不能把原版 L1 的约 7～8 μs 差距主要归因于 Torch profiler。第 8 节 ACLNN 在不同 profiler 下的变化是另一项实测结果，不能直接套到原版 PTO。
3. **ACLNN 不是在原 PyPTO/Simpler 执行链上再套一层。** 它复用生成的核计算代码，通过新的 MIX 包装入口启动，替换原运行时的启动、传参与调度路径。因此不能要求其设备耗时必然等于“原 L1 + 正开销”。
4. 当前已定位到执行方式及全核时间线变化；尚未隔离 Graph 路径中的缓存、调度、资源状态各自贡献，不能宣称找到某个固定的底层开销。两侧计时边界也并不完全相同，本表的亚微秒差值不能当作 ACLNN 固定封装成本。
